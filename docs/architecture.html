Data Flow — Filter Change Example

1
User changes filter in FilterBar
e.g. Warehouse → "London", Category → "Sensors"
2
useFilters() singleton ref updates
selectedLocation = "London"  |  selectedCategory = "Sensors"
Shared across all components — no prop drilling
3
Active view watch() fires → loadData()
watch([selectedLocation, selectedCategory, selectedPeriod, selectedStatus], loadData)
4
api.js builds HTTP request with query params
GET http://localhost:8001/api/inventory?warehouse=London&category=Sensors
5
FastAPI endpoint receives request
apply_filters(inventory_items, warehouse="London", category="Sensors")
Skips filters where value is None or "all"
6
Pydantic validates & returns response
List[InventoryItem] serialised to JSON
7
Vue ref updated → computed properties recalculate
inventoryItems.value = response  →  filteredItems (computed)  →  table re-renders

Shared State (Composables)

useFilters.js
  • selectedPeriod — YYYY-MM or Q1-2025 or "all"
  • selectedLocation — warehouse or "all"
  • selectedCategory — category or "all"
  • selectedStatus — order status or "all"
  • getCurrentFilters() — builds API query object
  • hasActiveFilters — computed boolean
  • Singleton: one instance across all components
useAuth.js
  • currentUser — mock user (name, email, role, avatar)
  • tasks — 4 hardcoded tasks with priority & due dates
  • getInitials() — derived from user name
  • logout() — alert-based stub
  • Language-aware: returns EN or JA user data
useI18n.js
  • Supported locales: en (English), ja (Japanese)
  • t(key, params) — nested key lookup with interpolation
  • translateProductName / Customer / Warehouse
  • currentCurrency — USD or JPY based on locale
  • setLocale() — persists to localStorage

Key Design Decisions

Filtering Strategy
Server-side + Client-side
Warehouse / category / status / month filtered by FastAPI. Free-text search (Inventory) filtered client-side on the response.
Reactivity Pattern
Refs + Computed
Raw API data stored in refs. All display values derived via computed properties — never mutate fetched data directly.
Global State
Singleton Composables
useFilters() returns the same ref instances everywhere. Filter changes in FilterBar cascade instantly to all active views.
Data Persistence
None (by design)
All changes are lost on server restart. JSON files are the source of truth. Suitable for demo / local development only.
Quarter Support
filter_by_month()
Accepts "2025-01" (direct) or "Q1-2025" (expanded to ["2025-01","2025-02","2025-03"]) before filtering orders by date.
i18n
Custom (no library)
Lightweight useI18n composable. Supports nested key lookup, parameter interpolation, and per-locale currency switching.
